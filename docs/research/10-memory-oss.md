# Open-source long-term memory for omnis (2026-09-20 research)

## 1. TL;DR

Hermes Agent and OpenClaw both use the same pattern: a local `MEMORY.md`/`USER.md` (+`SOUL.md`/`IDENTITY.md`) flat-file default, with a pluggable **MemoryProvider** (Honcho, Mem0, Supermemory, etc.) layered on top — a dual structure. This is the reality of the "open-source memory that Hermes/harness-style agents use" that Logan wants, and it is a proven architecture omnis can copy as-is. Since omnis already runs Postgres on the mini, instead of a heavy new dependency like Neo4j (Graphiti/Zep) we recommend a hybrid: **mem0 (OSS, Apache-2.0, TS SDK, pgvector support)** as the primary vector/semantic memory, and a bi-temporal entity table built directly on Postgres (borrowing Graphiti's valid/invalid timestamp schema) as the entity graph for Network/CRM. Honcho has the strongest benchmarks, but it is AGPL-3.0, which risks conflicting with the plan to ship omnis as an app later, so keep it as a fallback only.

## 2. Facts

- Hermes Agent's (NousResearch) built-in memory is two files, `~/.hermes/memories/MEMORY.md` (~2,200 chars) and `USER.md` (~1,375 chars); at session start they are injected into the system prompt as a "frozen snapshot" and managed with the `memory` tool (add/replace/remove). On overflow it returns an error rather than auto-compacting. — VERIFIED, https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md (fetched 2026-09-20)
- `SOUL.md`/`AGENTS.md` are treated as information already present in context and are deliberately excluded from memory storage (to avoid duplication). — VERIFIED, same source as above
- Hermes makes external memory pluggable through the `MemoryProvider` ABC in `agent/memory_provider.py`. Interface: `name`, `is_available()`, `initialize()`, `get_tool_schemas()`, `handle_tool_call()`, `get_config_schema()`, `save_config()` + optional hooks `prefetch()`/`sync_turn()`/`on_session_end()`/`on_pre_compress()`/`shutdown()`. Only **one external provider can be active** at a time. — VERIFIED, https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/memory-provider-plugin.md (fetched 2026-09-20)
- The list of external memory providers Hermes supports includes Honcho, OpenViking, Mem0, Hindsight, Holographic, RetainDB, ByteRover, and Supermemory. — VERIFIED (cross-checked across multiple WebSearch results, fetched 2026-09-20); some of the lists come from a third-party write-up (hermesatlas.com), so trust that the providers exist but treat completeness as unverified.
- A separate session_search (SQLite full-text) makes the entire past conversation history searchable, working around the MEMORY.md size limit. — VERIFIED, memory.md source above
- OpenClaw (openclaw/openclaw, **390,095 stars** on GitHub, TypeScript, license: NOASSERTION — no standard OSS license file) uses Workspace Markdown (`USER.md`, `MEMORY.md`, `IDENTITY.md`) by default, with manual updates and no automatic cross-session persistence as the default. Attaching Honcho adds automatic persistence + user/agent profile modeling + semantic search, and the official docs state that "Honcho and the built-in markdown memory can work together." — VERIFIED, https://docs.openclaw.ai/concepts/memory-honcho (fetched 2026-09-20); star/license queried directly via `gh api repos/openclaw/openclaw` (fetched 2026-09-20)
- Honcho (plastic-labs/honcho): GitHub **7,258 stars**, license **AGPL-3.0**, Python FastAPI core + Python (`honcho-ai`)/TypeScript (`@honcho-ai/sdk`) SDKs. Through the "peer" concept it models users, agents, groups, projects, and ideas all as the same first-class entity, and after a conversation it runs reasoning asynchronously to produce a structured representation ("reasoning-first", not retrieval-first). It supports three deployment modes: managed (api.honcho.dev), `honcho start` (local stack), and fully self-hosted (Docker Compose). Integration docs exist for Claude Code/OpenCode/OpenClaw/Hermes. — VERIFIED, `gh api repos/plastic-labs/honcho` + README (fetched 2026-09-20)
- mem0 (mem0ai/mem0): GitHub **65,649 stars**, license **Apache-2.0**, Python core. OSS mode runs fully locally via the `Memory`/`AsyncMemory` classes (configure the LLM+embedder as Ollama and the vector store as Qdrant/Chroma/pgvector). The TypeScript SDK is the npm `mem0ai` package, and local mode is supported through the OSS subpath `mem0ai/oss`. It also has a Graph memory feature (Neo4j option), but that is not a core feature and requires separate configuration. — VERIFIED, `gh api repos/mem0ai/mem0` + WebSearch cross-check (fetched 2026-09-20)
- Zep changed its open-source strategy in 2026: it **discontinued** maintenance of the original "Zep Community Edition" (the memory service itself) and decided to concentrate on **Graphiti** (the temporal knowledge graph engine) as its only active open-source project. The reason was discomfort with the open-core approach (deliberately limiting features to steer users toward paid tiers). The existing Zep CE repository stays public under Apache-2.0 but is no longer updated. — VERIFIED, https://blog.getzep.com/announcing-a-new-direction-for-zeps-open-source-strategy/ (fetched 2026-09-20)
- Graphiti (getzep/graphiti): GitHub **31,013 stars**, license **Apache-2.0**. A **true bi-temporal** model that attaches four timestamps to every edge (relationship): when the fact actually became valid/became invalid (valid time), and when the system learned the fact/learned it is no longer true (transaction time). Supports Neo4j, FalkorDB, and Amazon Neptune as backends (there is no native TS SDK — the structure is to run it as a Python service and call it over HTTP/MCP). — VERIFIED, `gh api repos/getzep/graphiti` + https://www.getzep.com/ai-agents/temporal-knowledge-graph/ (fetched 2026-09-20)
- Letta (letta-ai/letta, formerly MemGPT): GitHub **24,801 stars**, license **Apache-2.0**. The core idea is OS-inspired 2-tier memory (in-context core memory + out-of-context archival/recall memory, paged by the LLM itself). The entire agent runtime (server plus desktop app) is heavy — it is not a simple memory library but a complete agent platform. — VERIFIED, `gh api repos/letta-ai/letta` + WebSearch (fetched 2026-09-20)
- cognee (topoteretes/cognee): GitHub **30,842 stars**, license **Apache-2.0**. A self-hosted knowledge graph engine specialized in ingesting arbitrary formats — documents, code, tickets, conversations — and linking them into a graph (the "ECL" ingest pipeline). Its positioning is strength in document/knowledge-corpus integration rather than conversational session memory. — VERIFIED, `gh api repos/topoteretes/cognee` (fetched 2026-09-20)
- LangMem (langchain-ai/langmem): GitHub **1,672 stars**, license **MIT**. Functional primitives that work without LangGraph (Memory Manager: extract/update/delete/merge, Prompt Optimizer); closer to a "memory logic library" than a service that provides storage itself. — VERIFIED, `gh api repos/langchain-ai/langmem` (fetched 2026-09-20)
- supermemory (supermemoryai/supermemory): GitHub **30,573 stars**, license **MIT**, TypeScript. A memory+RAG+connector unified API that advertises "can run fully locally." It is mentioned directly as the minimal-setup (API key only) example in Hermes Agent's official memory-provider docs. — VERIFIED, `gh api repos/supermemoryai/supermemory` + Hermes memory-provider-plugin.md (fetched 2026-09-20)
- Memori (GibsonAI/memori): GitHub **16,836 stars**, license field reported by the GitHub API as `NOASSERTION` (no standard/clear SPDX license file detected — check the LICENSE file directly before use). A SQL-native (SQLite/Postgres/MySQL) memory engine that attaches memory to existing LLM calls with a single line, `memori.enable()`, with two modes: conscious_ingest (short-term working memory) and auto_ingest (DB search). — VERIFIED stars/structure, UNVERIFIED exact license (`gh api` basis, re-check needed), fetched 2026-09-20

## 4. Recommendation for omnis

We recommend a **hybrid 3-layer** approach. Do not bet everything on a single vendor.

1. **Self-model layer (S, low risk)**: replicate the Hermes/OpenClaw pattern as-is — `~/.omnis/memory/USER.md`, `SOUL.md` (Logan's preferences/tone/relationship context), `AGENTS.md` (per-agent rules). Inject them into the system prompt as a frozen snapshot at session start, manage them with add/replace/remove tools, and compensate for the character limit with session_search (Postgres full-text — reuse the Postgres already on the mini instead of SQLite). Zero new dependencies.
2. **Episodic/semantic layer (S~M, low risk)**: adopt **mem0 OSS** as the primary store for ingestion of inbox messages (Slack/Kakao/Gmail/Telegram, etc.) + local files + Drive + GitHub. Reasons: Apache-2.0 (no distribution worries), a TS SDK exists, it can run fully locally on the already-planned Postgres+pgvector (embeddings from either a low-cost model on Vercel AI Gateway or a local embedding model), and at 65k stars it carries the lowest maintenance risk. Its weak bi-temporal support is not critical at omnis's scale (one person, small data volume).
3. **Entity/Network layer (M, low risk)**: rather than bringing in Graphiti or Honcho wholesale, use a **bespoke entity table** in Postgres (person, org, relationship, fact) and borrow only Graphiti's 4-timestamp bi-temporal columns (`valid_from`, `valid_until`, `recorded_at`, `invalidated_at`) as the schema. Queries the Network/CRM features require — such as "when did I last talk to this person, and what did I promise then" — are amply covered by a schema this size, and you do not have to put a new runtime (Neo4j/FalkorDB) on a 16GB mini.

**Fallback**: if mem0's reasoning quality falls short of expectations (especially contradiction handling and user profiling), switch to **Honcho self-hosted**. Honcho is the strongest on benchmarks and its peer model fits the Network features best conceptually, but **AGPL-3.0 is a risk** — if you plan to package omnis as an app and distribute/sell it later (the brief explicitly states the goal of "eventually a local MacBook + iPhone download service"), then if you modify Honcho's code and use it, serving it over a network can trigger the source-disclosure obligation. Isolating Honcho so you only call it through its API (self-host it unmodified, in a separate process) greatly reduces that risk.

**What not to do**: Letta (bringing in the entire agent runtime overlaps in role, since omnis is itself already an agentic orchestration layer), and making Graphiti the primary store (the full Neo4j operating cost is excessive for a one-person project — revisit it with FalkorDB later only if graph quality really proves insufficient).

## 5. What to borrow

- **The architecture itself**: take Hermes's "built-in flat-file + pluggable MemoryProvider, only one active at a time" pattern as-is. Reference: `NousResearch/hermes-agent` → `agent/memory_provider.py` (ABC), `website/docs/developer-guide/memory-provider-plugin.md` (interface spec: `initialize`, `get_tool_schemas`, `handle_tool_call`, `prefetch`, `sync_turn`, `on_pre_compress`).
- **frozen-snapshot design**: memory changes during a session are written to disk immediately but only take effect in the prompt from the next session onward — a trick to keep the LLM prefix cache warm. omnis also has multiple inbox channels triggering LLM calls at the same time, so this applies directly to reducing caching costs.
- **Capacity-management UX**: rather than automatic compaction, having the agent itself find the "items to delete" (Hermes memory.md) — it is handled inside the agent's turn with no separate batch job, so implementation cost is low.
- **The "both can be on" principle**: just as the OpenClaw official docs state that "built-in markdown + Honcho can work together", omnis should likewise separate and run the self-model (markdown) and episodic (mem0) layers in parallel — this is the basis for the 3-layer recommendation above.
- **Honcho's peer concept**: do not borrow the code, borrow the data model — apply the frame that "user, agent, group, project, and idea are all the same first-class entity" directly to omnis's Network/CRM schema design (not just people: projects and agent sessions too, with the same table pattern).
- **Graphiti's bi-temporal edge schema**: port Graphiti's (`getzep/graphiti`) four edge timestamps (valid_at/invalid_at/created_at/expired_at) design directly into Postgres table columns.
- **Supermemory's minimal-setup UX**: the setup-wizard pattern in which Supermemory, in the Hermes provider docs, "asks for just one API key and handles the rest itself" — a reference for the per-channel connection UX in omnis's onboarding (first-time Mac mini setup).

## 6. Open questions

- Whether mem0 OSS can cover Network/CRM "relationship" queries (e.g. "people I was introduced to through this person") with a pure vector + entity-table combination, without enabling its graph memory feature (Neo4j option) — needs validation with an actual prototype.
- Whether Honcho's AGPL-3.0 is genuinely safe under a "self-hosted, unmodified, called only through its API" configuration — this is a project decision rather than license advice, so Logan needs to confirm it.
- Memori's (GibsonAI) exact license showing up as NOASSERTION in the GitHub API — the LICENSE file needs to be read directly (a false positive is possible).
- The ToS risk of feeding data collected from channels without APIs, such as KakaoTalk/LinkedIn, into the memory pipeline is outside this research's scope (it should be covered by the separate channel-collection research).
- Embedding cost: there is still no measured latency/accuracy comparison between low-cost/open embedding models on Vercel AI Gateway and local (Apple Silicon MLX) embeddings.
- The OpenViking, Hindsight, Holographic, RetainDB, and ByteRover providers Hermes lists were not individually verified in this research (judged out of scope for this submission; follow-up research if needed).
