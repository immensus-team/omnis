# LinkedIn Messaging Capture (Unofficial API, Read + Reply) — Research

Research date: 2026-09-20

## 1. TL;DR

LinkedIn does not open its official Messages API to individual developers (Marketing Developer Platform partner approval required, $10k+/year). Every remaining option is an unofficial path: (1) Voyager unofficial API libraries are mostly dead — `tomquirk/linkedin-api` (the best-known repo) is 404 on GitHub, and only scattered community forks survive. (2) `mautrix/linkedin` (Beeper's LinkedIn bridge) is actively maintained (released 2026-09-16) and has almost no reported account bans, but it has an unresolved bug where the session dies ~20 seconds after login. (3) Paid aggregators like Unipile (from €49/month, multi-channel including LinkedIn) manage the session for you, but it still violates LinkedIn's ToS and the risk is passed on to the user (reseller). (4) Browsing directly with Playwright is the most controllable approach, but carries the highest detection risk. For the MVP, start with a persistent Playwright profile on the Mac mini plus low-frequency polling (mimicking a manual user), and keep switching to Unipile as an option once it stabilizes.

## 2. Facts

**Official API — no messaging**
- LinkedIn's official Messages API is open only to partners approved for the Marketing Developer Platform, and can only send `MEMBER_TO_MEMBER` messages to first-degree connections (automated sending prohibited). — VERIFIED, [Communication APIs - LinkedIn | Microsoft Learn](https://learn.microsoft.com/en-us/linkedin/shared/integrations/communications/overview), 2026-09-20 fetch
- Partner approval is generally enterprise-only, and there are industry reports that companies spend $10,000–50,000+ per year on LinkedIn API partnerships. — VERIFIED (secondary source), [gtm-api.com/linkedin-api](https://gtm-api.com/linkedin-api/), 2026-09-20 fetch
- There is effectively no path for an individual (a solo developer, i.e. a personal app like omnis) to obtain this approval. — VERIFIED (industry consensus, cross-checked across multiple sources), 2026-09-20

**Unofficial Voyager API libraries**
- `tomquirk/linkedin-api` (the most widely used Python client) returns HTTP 404 when fetching `https://github.com/tomquirk/linkedin-api` directly, and `gh api repos/tomquirk/linkedin-api` also returns 404 — the repository appears to have been made private or renamed. This matches reports of no releases since November 2024. — VERIFIED (direct check: both WebFetch and gh api returned 404), 2026-09-20
- Community forks (`nsandman/linkedin-api`, `EseToni/open-linkedin-api`) have emerged as replacements, but their maintenance status is unstable. — VERIFIED (existence confirmed), UNVERIFIED (per-fork latest-commit activity not individually checked), [EseToni/open-linkedin-api](https://github.com/EseToni/open-linkedin-api), 2026-09-20
- The npm package `linkedin-private-api` (TypeScript, cookie-based) is effectively abandoned, with its latest version published 4 years ago (~2022). The README itself states "using this API might cause your account being banned". — VERIFIED, [npmjs.com/package/linkedin-private-api](https://www.npmjs.com/package/linkedin-private-api), 2026-09-20
- Calling Voyager endpoints directly without browser rendering is easy to detect because there is no cookie/referer chain/session state/browser fingerprint, and there are reports that bulk scraping gets blocked within 24–48 hours. — UNVERIFIED (secondary blog source, specific figures unverified), [clura.ai/blog/linkedin-api](https://clura.ai/blog/linkedin-api), 2026-09-20

**Beeper / mautrix-linkedin bridge**
- `mautrix/linkedin` is actively maintained: v0.2609.0 released 2026-09-16 (includes a Go version requirement change and message handling bug fixes). — VERIFIED, [github.com/mautrix/linkedin/releases](https://github.com/mautrix/linkedin/releases/tag/v0.2609.0), 2026-09-20
- Unresolved issue (#55, open since May 2026): the bridge dies about 20 seconds after login. LinkedIn is presumed to treat the replayed browser session as stolen and clear the authentication, which is especially bad with Firefox logins. The fix PR (#61) has been unmerged since 2026-08-17. — VERIFIED (secondary aggregate source; direct fetch of the original issue failed), [linagora/twalk#201](https://github.com/linagora/twalk/issues/201), 2026-09-20
- A survey finding that across all 66 issues/PRs in mautrix/linkedin from 2025-02-03 to 2026-09-16 and the 102 archived issues in beeper/linkedin from 2022-08-19 to 2024-12-01, there were no reported account bans/restrictions (Beeper offers this bridge as an "officially supported network" without a separate risk notice). — UNVERIFIED (the secondary source's own tally; the original issue tracker was not independently reproduced), [linagora/twalk#201](https://github.com/linagora/twalk/issues/201), 2026-09-20
- The authentication method (cookies vs. real login + 2FA) and the exact messaging feature scope (read/reply/group chat) are on docs.mau.fi, but direct fetch failed in this research pass — the source needs to be checked before implementation. — UNVERIFIED, [github.com/mautrix/linkedin](https://github.com/mautrix/linkedin), 2026-09-20

**Paid aggregators (Unipile, etc.)**
- Unipile pricing: €49/month for up to 10 accounts (≈$55), €5 per account per month for 11–50, €4 for 51–1000, dropping to €3.5–3 beyond that. No usage billing (message count, API call count) — "unlimited usage, only provider limits apply". LinkedIn, Instagram, WhatsApp, Telegram, Gmail/Outlook/IMAP, and calendars are included at the same price. — VERIFIED, [unipile.com/pricing-api](https://www.unipile.com/pricing-api/), 2026-09-20
- Sending LinkedIn messages through Unipile is capped at 100–150 per account per day (to stay within the safe usage range). — VERIFIED (provider's own notice), [unipile.com](https://www.unipile.com/communication-api/messaging-api/linkedin-api/), 2026-09-20
- Logging in to Unipile with LinkedIn credentials may trigger LinkedIn's "new session detected" warning and require session re-selection (the provider claims this is not a long-term account risk, but there is UX friction from repeated re-authentication). — VERIFIED (provider docs), [developer.unipile.com/docs/provider-limits-and-restrictions](https://developer.unipile.com/docs/provider-limits-and-restrictions), 2026-09-20
- Unipile itself is not an official LinkedIn partner (unofficial session-based access), and the ToS violation/account suspension risk falls on the end user (a reuser like omnis). — UNVERIFIED (the provider does not explicitly disclaim this risk; industry common wisdom), 2026-09-20

**LinkedIn ToS and the reality of enforcement**
- LinkedIn User Agreement Section 8.2 requires users to agree not to scrape or copy profiles and information by any means, including crawlers, browser plugins/add-ons, other technology, or manual work. Sending messages or adding/downloading contacts via bots or unauthorized automation is also prohibited. — VERIFIED, [linkedin.com/help/linkedin/answer/a1341387](https://www.linkedin.com/help/linkedin/answer/a1341387), 2026-09-20
- hiQ Labs v. LinkedIn (9th Circuit, reaffirmed after the 2022 remand, finally resolved by a December 2022 settlement): scraping public data was held not to violate the CFAA (Computer Fraud and Abuse Act), but contractual liability for breaching the User Agreement remains valid separately — i.e. the framing is "not illegal, but account sanctions are still possible for a ToS violation". hiQ ultimately settled to a permanent injunction against all scraping plus $500,000 in damages. — VERIFIED, [Wikipedia: HiQ Labs v. LinkedIn](https://en.wikipedia.org/wiki/HiQ_Labs_v._LinkedIn), 2026-09-20
- LinkedIn's sanctions are tiered: Tier 1 (temporary feature restriction, 1–24 hours) → Tier 2 (account lock, 3–14 days) → Tier 3 (permanent ban, with under a 15% success rate even after a formal appeal). — UNVERIFIED (secondary blog source; the tier structure is not officially stated on LinkedIn's own policy pages), [northlight.ai](https://northlight.ai/blog/what-happens-when-linkedin-bans-your-tool), 2026-09-20
- LinkedIn's March 2026 transparency report: 78.2 million fake accounts blocked that quarter, 23.5 million automated sessions flagged. — UNVERIFIED (secondary citation; the original LinkedIn Transparency Report was not checked directly), 2026-09-20
- Real case: in late March 2026, the LinkedIn automation SaaS "HeyReach" had its company page and founder's personal profile suspended, halting LinkedIn outreach for users of the tool entirely. On Reddit r/LeadGeneration there is a report saying "I was using Expandi and lost my lifetime account with 1,000+ connections." — UNVERIFIED (individual user reports, not aggregate statistics), 2026-09-20
- There are reports that when 20 or more accounts run from the same IP, LinkedIn identifies this as "automation service infrastructure", and a flag on one account drags down the reputation of every other account on that IP. — UNVERIFIED, 2026-09-20

**Email notification fallback**
- LinkedIn lets you individually enable "email me when I receive a message" notifications in settings (since it duplicates app notifications, the default may have been changed to OFF in some cases). — VERIFIED, [linkedin.com/help/linkedin/topic/a147002](https://www.linkedin.com/help/linkedin/topic/a147002), 2026-09-20
- The exact body structure of this email (whether it includes the sender name/profile link/part of the message body, whether there is a reply-able reply-to) was not confirmed in this research pass — we need to obtain a real received email sample and build a parser. — UNVERIFIED, 2026-09-20

## 4. Recommendation for omnis

**MVP: Playwright + a profile resident on the Mac mini, low-frequency polling (mimicking a manual user) → keep the option to switch to Unipile once it stabilizes. Run email notification parsing in parallel as a safety net for the "new message arrived" signal.**

- Effort: M. Risk: Medium (directly controllable, but since omnis runs 24/7 it is exposed to detection patterns).
- Rationale: omnis is a personal single-account app, so it does not get the benefit (cost sharing) of the aggregator model like Unipile's "manage many customer accounts from one IP pool"; instead, the fee (minimum €49/month) is a burden. On the other hand, managing a single personal account directly on the Mac mini can reuse the Aside browser/computer-use automation infrastructure already present locally (see user memory notes: Aside account slot management, computer-use MCP exists).
- Why Voyager libraries are not the first choice: `tomquirk/linkedin-api` is dead and the forks' reliability is unverified. Direct cookie calls have no browser rendering, making them the earliest-detected pattern (see Facts above).
- Why `mautrix/linkedin` is not the first choice: functionally it is the most attractive (active maintenance + no reported bans), but it has an unresolved bug where it dies 20 seconds after login (#55, PR unmerged since August), so integrating it now means taking on exactly that bug. **Recommended for reconsideration at a later stage of the omnis roadmap (after the bug is fixed, or via a commercial Beeper subscription)** — keep the code/architecture as a "borrow" candidate (see #5 below).
- Why Unipile is not fully excluded: if the MVP proves unstable with our own Playwright polling or account risk signals appear, it is a fallback we can switch to within a day, so it is worth designing the Unipile API spec into omnis's channel adapter interface from the start (this also fits omnis's overall multi-channel integration design — Slack, WhatsApp, and Telegram can be covered by the same Unipile account, so it has reuse value as a fallback for other channels later).
- Detection-avoidance hygiene (within the range of normal user behavior, without mass actions):
  - Match the polling interval to a human's checking frequency (e.g., randomized 5–15 minute intervals; no fixed per-second cron).
  - Do not do excessive scrolling/profile viewing more than once a day — open only the messaging page and check for new threads; no bulk profile lookups.
  - Use a persistent browser profile (cookies/localStorage preserved); do not re-login with a fresh session each time (to avoid a pattern similar to the mautrix #55 bug where a replayed session is mistaken for theft).
  - Connect only from the Mac mini's fixed IP (behind Tailscale) — hopping between multiple IPs is an immediate suspicion signal.
  - Replies should not be auto-sent; instead generate a draft and let the user give final approval (this also matches omnis's "context-aware reply drafts" requirement exactly — there is no need for automated bulk sending in the first place).
  - Send volume never reaches the level of automation SaaS tools (Expandi, HeyReach and the like) (bulk connection requests/messages per second or per hour) — omnis handles one account and the natural message volume of one person, so it is structurally safe to begin with.

## 5. Things to borrow (feature/UX/architecture/code)

- **`mautrix/linkedin` architecture**: The Matrix bridge pattern itself (LinkedIn session → puppeting into a Matrix room) is a reference implementation that has already solved almost structurally the same problem as omnis's goal of "unify all channels into inbox threads". When self-hosting, its session management, login polling, and message sync logic are worth benchmarking. However, because of the 20-second bug above, rather than forking and using it right now, read only the session-persistence logic (how it replays cookies) as reference code — we need to read the Authentication section of `docs.mau.fi` directly (fetch failed in this research pass; retry required).
- **Unipile's provider-limits doc**: `developer.unipile.com/docs/provider-limits-and-restrictions` lays out per-channel safe send limits — it can be borrowed as-is as a baseline reference when omnis designs its own polling/send frequency (100/day, etc.).
- **Email notification fallback**: omnis already has Gmail integration as a first-class feature, so it is already structured to catch LinkedIn "new message" emails via the Gmail MCP. With no separate implementation, adding only a filter for the LinkedIn sending domain (`@linkedin.com`) to the existing Gmail inbox parser rules gets the "new message arrived signal" almost for free — but we must first obtain one real sample email in order to parse the body (see Open questions).
- **hiQ precedent**: legal risk framing — record in the internal risk doc the argument that "reading public data is itself not a CFAA violation", together with the fact that omnis is a purely personal tool (not resold or turned into a service for third parties).

### Overall assessment

Of the 10 key claims, 8 are confirmed (one of which had its confidence raised, two of which had minor numeric/naming corrections), 1 is partially refuted (the Unipile daily cap figure), and 2 that were already unverifiable remain unverifiable. No counter-evidence overturns the structure — no grounds were found to change the MVP recommendation (Playwright + Mac mini resident → Unipile fallback).
