# GAP 4: Screenshot-based hands-on teardown of Kinso (2026-09-20 research)

The original screenshot/mockup images are stored in `omnis/research/assets/kinso-teardown-2026-09-20/` (hero-desktop.png, hero-mobile.png, morning-briefing-dark.png, integration-icons.png, notif-card-*.png — all downloaded directly from kinso.ai's official CDN (framerusercontent.com) on 2026-09-20).

## 1. TL;DR

We inspected kinso.ai's actual UI, which text fetches could not show, with a browser + DOM inspection (extracting image URLs directly, `getComputedStyle`). Key findings: (1) A list row is structured as circular avatar + bold name + gray timestamp + one line of gray preview + channel brand icon on the right, and only the selected row is distinguished by a white card floating slightly above the background with elevation (soft shadow)—no hairline dividers are used. (2) There is no dark **mode** (no color-scheme meta, no dark class at all, confirmed via the DOM), but dark **sections** do exist (morning briefing, voice features)—grid texture + orange→teal gradient orb accents. (3) Search bars/input fields are all pills (full-radius), with an orange-teal gradient stroke on focus. (4) Measured logo/accent colors: teal `#497E7E`→light gray `#E7EAED`→orange `#EF5520`→rust `#9F2B04`. (5) The channel list is officially confirmed from a primary source (Gmail, LinkedIn, Slack, WhatsApp, Instagram). (6) There is again no evidence of a native app (every CTA is only "Join"/"Waitlist", no App Store link)—the only basis for omnis's "web-first vs. native" decision is the absence-of-evidence that they "didn't build one". (7) The waitlist number changes on every page load (27,300→24,566→32,754)—confirmed unreliable. (8) An Instagram post caption mentions "onboarded 1,000 users", and a "We Failed To Launch...(kinda)" video exists on YouTube—actual users are far fewer than the waitlist count, and the launch was likely not smooth.

VERIFIED.
- List row: circular avatar (photo), **name (bold, ~20px estimated) + timestamp (gray, small, right-aligned on the same line)**, below it preview text (gray, 1 line, truncated without an ellipsis), and at the far right of the row a colored brand icon (indicating the source channel). VERIFIED.

The other rows merely sit on a light gray (off-white) background without being turned into cards, and no hairline dividers between rows are visible—density is managed by padding alone. VERIFIED.

VERIFIED (individual card images `fx3BQ9tj...`, `pdnVm6k5...` confirmed directly).

**Typography / color / motion**

VERIFIED (extracted directly with `getComputedStyle`).

VERIFIED (queried the DOM directly, re-confirmed at the mobile viewport).

## 4. Recommendation for omnis

**Narrow the visual-language borrowing to three things: "card elevation + icon-based channel identification + dual gradient accent."** Kinso's list isolates only the selected row as a floating card without hairline dividers, which is a different axis from Linear/Raycast's hairline-based density. If omnis is going to mix 8 channels (Slack/Kakao/Gmail/Outlook/Telegram/LinkedIn/WhatsApp/agent sessions) in a single list, kinso's approach—**channel identification via a small brand icon at a fixed position on the right rather than avatar color**—is genuinely advantageous: avatars can be dedicated to "who sent it" and icons to "where it came from", separating the information channels. effort **S** (a design decision; the implementation itself is adding one icon slot to the list component), no risk.

**There is nothing to learn from kinso on dark mode—design it independently.** kinso.ai has no system dark mode; all it has is content-section-level "dark block" styling. omnis is a real productivity app used all day, so dark mode is mandatory; `14`'s decision to pull dark tokens (near-black canvas `#08090a`, `#07080a`) from Linear/Raycast was a valid choice, and this kinso investigation provides no grounds to change it. effort N/A (already covered in `14`), no risk—but `14` §7's open question of "porting kinso's actual screens into Figma to extract tokens precisely" can now be settled by this investigation as **having no answer at all with respect to dark mode**, so `14` should be corrected to cite kinso only as a light-mode/layout reference.

**Do not use kinso as grounds in the platform decision (Mac native vs. web).** kinso itself appears to have shipped nothing yet (waitlist only, no download links whatsoever). There is no basis on which to build the argument "the reference product shipped as a Mac app, so we should too"—whether omnis has a Mac app must be decided purely on its own requirements (Mac mini hub + always-on + need for Accessibility APIs, see `18`). effort/risk N/A (confirming the absence of information is itself the conclusion).

**Do not use waitlist/social metrics as a competitive benchmark.** A 27k~32k waitlist and 82.5k/56.6k followers are the output of content marketing (171 YouTube videos), not indicators of product maturity—Instagram's self-disclosed "1,000 onboarded" is a far more realistic number. omnis is a single-user product, so these metrics are meaningless to begin with, but be careful not to over-fit the design-fidelity target to the impression that "kinso is big." effort/risk N/A.

**From a risk standpoint (ToS/account bans/maintenance)**: this investigation only collected screenshots and performed no login or scraping automation (no bypassing Instagram's login wall, no robots violations)—no added risk. Note, however, that kinso.ai's marketing images (logo, product mockups) are copyrighted assets, so do not reuse them verbatim in omnis's own UI; use them only as layout/pattern references. effort none, risk low (patterns are not subject to copyright protection; the images themselves are).

## 5. What to borrow

- **List row component**: avatar (circular, fixed size) + name (bold) + timestamp (same line, right-aligned or next to the name) + preview (gray, 1-line truncate) + brand icon slot at the far right. Can be adopted as-is as the first-pass spec for omnis's unified inbox list component. Reference image: `omnis/research/assets/kinso-teardown-2026-09-20/hero-desktop.png`.
- **Selected-row elevation pattern**: instead of hairline dividers, only the selected row floats as a white card + soft shadow—implementable 1:1 with shadcn/ui's `Card` + `hover:shadow-sm`, adding one `--shadow-row-selected` to the Tailwind tokens in `14` §6.
- **Pill input field + gradient stroke focus state**: directly applicable to the "Ask Kinso"/"Ask/Search" unified command bar. In CSS, implement with `border-image` or the double-background trick `background: linear-gradient(...) border-box, linear-gradient(...) padding-box`.
- **Dashed unread indicator**: a dashed circle instead of a solid dot—consider adopting it as a differentiator in omnis notification cards/toasts.
- **Channel icons = squircle tiles + colored glow halo** (see `integration-icons.png`): a pattern usable as-is for the "connected channels" grid in settings, and it connects naturally with iOS home-screen icon aesthetics (matching an Apple-native tone).
- **Morning briefing copy structure**: "Good morning, {name}. You've got N new and M active conversations." + "Today's briefing" CTA pill—reusable almost verbatim as the copy template for omnis's nightly archive digest / morning briefing (see `17`).
- **Voice interface UI**: mic icon in-input + "{Assistant} is speaking…" state label + chat bubbles—a screen structure to reference directly if omnis adds voice briefings (not a feature specified in the brief, but a possible future extension).

## 6. Open questions

- The exact corner radius px, the typographic scale (font-size/line-height ladder), and the font family name are only image-based estimates—precise values require either opening the actual file and tracing it after Figma MCP authentication, or systematically dumping kinso.ai's compiled CSS (`getComputedStyle` on actual text nodes) (the same as the existing open question in `14` §7).
- It is impossible to distinguish whether the macOS window frame in the desktop mockup is an actual Electron/Tauri/native app screenshot or a pure design mockup (a fake window made in Figma/a design tool)—judging from the high-resolution UI details (font rendering, anti-aliasing) the impression leans toward a design mockup, but this cannot be confirmed.
- The content of the "We Failed To Launch Australia's Most Viral Startup (kinda)" video was not actually watched—to judge kinso's product maturity/pivot status more accurately, this video and the sidebar video "Growing Kinso App From..." need to be watched and summarized.
- It is unclear exactly when kinso-site.webflow.io was created and whether it is still an active marketing channel (whether it is for A/B testing or a leftover old version).
- The actual UI (screen screenshot) of the Smart Contacts / contact history feature was not obtained in this investigation—only the copy was confirmed.
