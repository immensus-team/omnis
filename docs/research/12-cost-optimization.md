# LLM Cost Optimization Playbook + 2026 Model/Price Table (omnis)

## 1. TL;DR

omnis is a personal tool for a solo founder handling ~2,000 messages per day, so calling frontier models directly is wasteful. Core strategy: (1) run classification/labeling/embedding locally with MLX on the M5 Max MacBook (free, Qwen3.x-30B-A3B-class MoE at ~60 tok/s); the M4 16GB Mac mini has under 32GB, so MLX acceleration is unavailable — small embedding / 1–3B models only; (2) reply drafts default to DeepSeek V4.1 Flash with cache-hit-heavy prompt design, cascading to Claude Sonnet 5 only for VIP/high-risk threads; (3) schedule the nightly digest with the Batch API (50% discount) + DeepSeek's off-peak window (KST night–morning); (4) Claude Code/Codex CLI only within "ordinary individual use" of the already-owned Max/Plus subscriptions — routing OAuth tokens through the Agent SDK or a product backend is explicitly prohibited by Anthropic's ToS. Neither OpenRouter nor Vercel AI Gateway marks up tokens (OpenRouter charges only a 5.5% fee on credit purchases).

## 3. Options / Comparison

**Gateway choice — OpenRouter vs Vercel AI Gateway**

| | OpenRouter | Vercel AI Gateway |
|---|---|---|
| Token markup | None (pass-through) | None |
| Platform fee | 5.5% on card top-ups only | None on tokens; $0.10/1k req for ZDR+allowlists |
| Model breadth | 400+ models, 70+ providers, broadest China-model coverage (DeepSeek, Qwen, GLM, Kimi, MiniMax all listed) | Narrower catalog, tightly integrated with Vercel/AI SDK, good for Next.js-native apps |
| Routing | Aggregator: price/latency/throughput sort, explicit fallback chains | Same primitives (`order`/`only`/`sort`), Vercel-hosted uptime/latency picks by default |
| Caching | Passthrough, model-dependent | Passthrough, model-dependent (caching lives at the provider, not the gateway, in both) |
| Best fit for omnis | Primary gateway — cheapest Chinese models, broadest fallback | Secondary/optional — only if omnis's agent runtime is built with Vercel AI SDK/eve, for unified telemetry |

Both gateways are free of markup on tokens, so the real cost driver is **which underlying model** you pick per task, not which gateway. Use OpenRouter as the default multi-model router (bring-your-own-key against DeepSeek/Qwen/GLM/Kimi/MiniMax + Anthropic/Google/OpenAI for escalation) and only add Vercel AI Gateway if the agentic runtime is already on Vercel AI SDK for its native tool-calling/telemetry.

**Local vs cloud by omnis task**

| Task | Volume | Best fit | Why |
|---|---|---|---|
| Work/personal filter, auto-label | Very high (~all inbound) | Local (M5 Max MLX, 1–3B classifier) or Gemini 2.5/3 Flash-Lite fallback | Trivial classification; local = $0, cloud fallback = ~$0.10/$0.40 per M |
| Memory embedding | High | Local (M4 mini or M5 Max, small embedding model via Ollama/MLX) | No reasoning needed, privacy-sensitive personal data, avoid egress cost entirely |

| Memory consolidation / fact extraction | Low-medium, periodic | Claude Sonnet 5 or DeepSeek V4 Pro | Needs stronger synthesis than a draft; still cheap at this volume |
| Cross-session agent orchestration / planning | Low, high-stakes | Claude Sonnet 5 primary, Opus 5 only for hard planning; Claude Code CLI under existing Max subscription for actual dev work | Reasoning quality matters most here; subscription CLI is a sunk cost, not incremental spend |

## 4. Recommendation for omnis

Adopt a **4-tier model policy**, cascade-first, cache-aggressive, local-first for anything that doesn't need real reasoning:

1. **Tier 0 (free, local, M4 mini + M5 Max):** classification, auto-labeling, work/personal filter, embeddings. Effort: **M** (needs an MLX/Ollama pipeline stood up and a small labeled eval set to trust it) — Risk: low, no ToS exposure, but the M4 16GB mini genuinely can't run 32GB+ MLX models, so this is embeddings + 1–3B classifiers only; anything heavier routes to Tier 1.
2. **Tier 1 (cheap cloud default):** DeepSeek V4.1 Flash via OpenRouter for reply drafts, follow-up suggestions, note routing. Design prompts so the system/context prefix is stable and large (cache-hit heavy) and only the delta is cache-miss — at DeepSeek's rates this is close to free even at 2k msgs/day. Effort: **S**. Risk: low (China-hosted model — if data residency of personal inbox content is a concern, keep PII-heavy fields out of the prompt or route those specific threads to Tier 2 instead).
3. **Tier 2 (escalation):** Claude Sonnet 5 / Haiku 4.5 for VIP contacts, ambiguous-confidence drafts, memory consolidation, and any cross-agent orchestration logic. Trigger escalation on a simple confidence heuristic (Tier 1 self-reported uncertainty, or a cheap classifier flagging "high stakes"), not on every message. Effort: **S** (once the cascade trigger exists). Risk: low, standard API billing.
4. **Tier 3 (subscription, not API):** Claude Code CLI (Max) and Codex CLI (Plus/Pro) for the actual dev/build agents and for genuinely personal, ordinary-use agent sessions Logan runs himself — not as a hidden backend that omnis calls on behalf of "users" (there's only one user, but keep the binary unmodified and the auth flow native regardless, since that's exactly the ToS carve-out). Effort: **S** (already set up). Risk: **medium if the pattern drifts** — if omnis's inbox pipeline ever extracts the OAuth token and hits the Anthropic API directly instead of shelling out to the real `claude` binary, that crosses Anthropic's explicit prohibition and risks account action. Keep the boundary literal: omnis invokes the Claude Code binary as a subprocess/session, never as a token-harvested API client.

At ~2,000 messages/day (~60k/month), a back-of-envelope estimate with this cascade: local Tier 0 = $0; Tier 1 reply drafts (~300/day, cache-hit-heavy) ≈ **$2–5/month**; Tier 2 escalations (~10% of drafts + daily memory consolidation) ≈ **$10–30/month**; nightly batch digest ≈ **$2–5/month**. Total incremental API spend: **roughly $20–50/month**, excluding the Claude Max / ChatGPT Pro / claude-ds seats already paid for. This is a rough model-based estimate, not a measured bill — label it as such until real usage logs exist.

## 5. What to borrow

- **DeepSeek peak/off-peak pricing → job scheduling.** Off-peak (cheap) hours in KST are roughly 19:00–10:00 and all weekend (peak UTC windows 01–04 & 06–10 map to KST 10:00–13:00 and 15:00–19:00). Schedule the nightly archive digest and any bulk memory-consolidation batch jobs after 19:00 KST — concrete, free win, no code changes beyond a cron time.
- **RouteLLM's cascade pattern** (cheap-first, escalate on low confidence) — implement as a thin wrapper: call Tier 1, check a cheap heuristic (token-probability confidence if exposed, or a 1-line self-rated confidence in the response schema), escalate to Tier 2 only below threshold. This is the single highest-leverage lever cited across sources (60–85% reported savings) and is a small amount of code.
- **Anthropic's mid-conversation system message / prompt-caching prefix discipline** (from the bundled `claude-api` skill, `shared/prompt-caching.md`): keep tools → system → messages order stable, put timestamps/per-request IDs *after* the cache breakpoint. Directly reusable for omnis's reply-draft prompt template regardless of which model tier serves it.
- **Vercel AI SDK's provider routing config** (`order`/`only`/`sort` by cost/latency/throughput, `vercel.com/docs/ai-gateway/models-and-providers/provider-options`) — if omnis's agentic layer is built on the AI SDK per the brief, this gives fallback chains for free without a custom router.
- **Batch API discount (50%)** for the nightly digest specifically — it's explicitly designed for exactly this "non-urgent, process overnight" shape.
