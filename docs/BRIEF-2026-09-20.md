# omnis — Logan's original brief (verbatim, 2026-09-20)

* The project name is omnis. Put it up on the company GitHub, and let's start with planning first.
* Do all the planning with fable. For development, though, mix opus, sonnet, and deepseek V4.1 Flash as appropriate. Everything else is fine, but note that DeepSeek in particular is currently used via API.
* First, I'm going to build an app, and here's what it is:
   * Real-time All-in-one Unified Inbox (Slack, KakaoTalk, Gmail, Outlook, Telegram, LinkedIn, Whatsapp, Agent|Claude, Codex, Deepseek, Hermes, etc.)
      * The important thing here is that I must be able to grasp every message coming to me at a glance, and at the same time control all of them. And at the same time, with all my context preserved, I must be able to see my inbox and my agents all at once.
      * There's a filter feature that automatically distinguishes whether something is work or personal
      * As far as I know, LinkedIn and KakaoTalk have no API and in practice can't be used simultaneously from more than one computer. So my plan is to run everything needed on the Mac mini, and have everything collected there be usable from my MacBook and phone in the form of an app. An important consideration here is that the Mac mini's Codex agent and Hermes must be accessible and usable from omnis, and the MacBook's Codex agent, DeepSeek agent, and Hermes must all be accessible and usable too. **In the end, all of these are inboxes to us in the dimension of information and work.**
      * Integrate everything with my Google Calendar too. Communication and scheduling — the things needed to understand and coordinate the context of my work and life — must all be collected and reflected in the context.
      * There's an Archive feature, so let me review a nightly summary of the inbox items (especially email) that are unnecessary, already handled, or never looked at again.
   * Agent:
      * It will draft replies in real time and notify me separately. The draft here is not a simple automatic reply but a draft based on my context and the context of that conversation.
      * I'd like all context about me to be remembered as memory. Use an open-source memory feature for this, and since there are open-source memory projects that Hermes and other excellent harnessing models actually reference and use, let's proceed that way too. And this context memory should be built not only from memory originating in my inbox but by gathering all collectible data about me and my work — local, drive, github, and so on. And all of these must exist inside omnis, so that I can access and use them anytime from my MacBook or iPhone. If the Mac mini (or a virtual cloud) is the hub, then wherever I am I can gather my context about myself into one place, check it, and get work done. At the same time it applies to my work as well.
      * I'd like the agent to remind me of the things I need to do, matched to the unified inbox and my work context, and to naturally add the tasks I need to do. That will require its own to-do list — make it a to-do list that is handled together with the agent. And if there are things the agent can do in advance, have it assign work first to my Codex agent or my Hermes agent as appropriate (which will depend on where it needs access — the agent on the Mac mini or the one on the MacBook). So in practice the agent goes ahead and does all the work on its own to match every one of my inboxes.
      * Have the agent read the context of the people in the inbox on its own and auto-labeled peope according to topics. Same for work.
   * I'd also like a separate place where I can manage my Network. This is organized somewhat like contacts, and I thought it would be very good to be able to manage my network inside omnis from the standpoint of unifying the inbox. Within it: 1. since it knows the context of whom I meet and come back from, it should write follow-ups on its own, or remind me if it's someone I'm meeting for the first time; 2. it should manage the network so I can grasp whom or what I need to act on; and 3. all of this must be shareable as context too.
   * When I send a simple note, let it be reflected in whatever conversation context it belongs to. Who it would help to share that note with, which Network contact it would make a good follow-up and question for, and so on.
* If there are settings needed on my Mac mini, do all of that setup there, and on my MacBook I'll download and use it like an app. Same on my iPhone. It must sync in real time. The local hermes, codex, and deepseek on my MacBook and the agents on the Mac mini must be able to talk to each other and assign work to each other within the same context (such as fetching local files, depending on the situation).
* All the way to letting the inbox and the agent sessions mutually understand and act with one another. So that the agents can understand all the other conversations and understand the other sessions, and organically carry out work that fits the purpose.
* For now I'm trying to overcome the limitations these services have by connecting omnis across Mac mini–MacBook–phone (and of course there are certainly more varied things we can try while making use of the Mac mini here), but later on I'd like omnis to become a service I can simply download and use directly on a local MacBook and phone. Plan with that in mind from the start.
* There will be a huge number of open-source projects we can reference in advance for product planning in relation to what we're trying to do (for example, Google's Artemis for mobile just came out recently). Let's run research across subagents (sonnet, haiku) to scrape them all, and take everything we can draw inspiration from. Whether that's a simple agent structure, a feature, UI/UX, and so on. If the development process for the features we need requires things like a kernel, plan those out as well.
* For UI/UX, you can reference an app called kinso, and make it as Apple-like as possible. Trendy yet intuitive, easy to use, and cold. Use every relevant plugin there is.
* When developing, if what we need is not a simple system but an agentic system for operating omnis, let's build and refine it ourselves using things like the Vercel AI SDK or Vercel Eve. omnis has to become the best agentic system there is. And for that too, choose the best harnessing for our needs. Just adopt and apply the harnessing that best suits the direction and features of the service we're building.
* Cost optimization is needed too (we don't have money...). Whether to use OpenRouter or Vercel Gateway to run cheap Chinese models, whether to run cheap or open-source models in parallel to get performance, whether to base things on subscription-based frontier models, and so on — plan this part out well too, and in particular research and adopt the Silicon Valley approach to cost optimization, then plan and develop with it.
* There will be many things we can draw inspiration from and plan around in the commercial products and open-source projects we can get our hands on, such as the kinso app (https://www.kinso.ai/) and buzz (https://github.com/block/buzz). Whether it's the actual product's UI/UX, features, how it works, its structure — anything at all.
* Let's plan every part of omnis completely and in detail, starting from the product definition. With real usability in mind. For AI usage here, fable holds the overall planning flow, and for everything else that supports it, prompt and use lower models well. And the planning document must thoroughly cover everything from omnis's definition and structure through to the goals that start from them.
* Lastly, once the planning document is complete, don't stop there — start developing our service right away. Here too, have fable orchestrate and mix deepseek v4.1 flash, opus, sonnet, and haiku as appropriate. Continue development in a ralph loop style to achieve the goals in the planning document.
* When putting it on GitHub, don't just do a plain readme — let's make ours really impressive, like the hot repos such as hermes or openclaw do. Visually stunning enough to make people gasp.

*Never try to handle everything with fable. fable is the best brain, and its role is to manage, combine, and advance things so that it can get the best results by assigning all the work to lower models. The work itself will already be done well by the other models if fable commands them in detail.*
