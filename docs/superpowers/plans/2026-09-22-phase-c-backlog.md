# Phase C Story Backlog (2026-09-22)

This splits master §16's **Phase C — capture channels + todos + Network** into 32 stories (US-C00–US-C31). Order = dependency order: every dependency has a lower number than its dependent. The backlog has **two waves**:

- **W1 — FIXTURE-FIRST (US-C00–US-C18), runnable now.** No real account, no mini GUI session, no Keychain secret, no live Hermes. Every story is accepted on fixtures, mock clients, mock SSE or a mock runtime (the B-D5 rule carries over as C-D1).
- **W2 — LIVE (US-C19–US-C31).** Each one needs a real account, the mini's GUI session, or a spike gate, and names the gate it waits on. None of them starts before its gate row in §5 says PASS (or, for the whatsmeow fallback, FAIL).

The executable plan is [`2026-09-22-phase-c-plan.md`](2026-09-22-phase-c-plan.md) (one plan file, two waves).

- Parent: `docs/spec/00-omnis-design.md` v1.0 §8·§9·§16 (Phase C row)·§19 Q2/Q3/Q7/Q10/Q12; A1 §1.7·§2.6–§2.9·§3·§4; A2 §0·§4.4·§5·§6·§7·§8.3; A4 §4.4·§5; A7 §3–§4.
- Contract: Phase A `2026-09-20-phase-a-interfaces.md` + Phase B `2026-09-20-phase-b-interfaces-delta.md`. What Phase C adds to the contract is fixed by **US-C00** (§3 below lists it verbatim).
- Baseline code: `main` cca0c7b (Phase B's 45 stories + product loop round 1 merged).
- Design: `docs/design/DESIGN-DIRECTION.md` + the preamble/checklist in `docs/design/SKILLS.md` for every UI story.

## 1. Decisions this backlog locks in (C-D1–C-D8)

| # | Decision | Rationale | If reversed |
|---|---|---|---|
| **C-D1** | **Fixture-first.** A W1 story never needs a real account, the mini's GUI session, a Keychain value, or a live Hermes. Capture-channel fixtures that no one has captured yet are synthesized from the vendor docs and carry `"provenance": "synthetic-from-docs"`; the matching W2 story replaces them with redacted captured payloads under `fixtures/captured/` and the tests must pass on both | Carries B-D5 forward. Gates ②③④ are open (§0), so waiting on them would block the whole phase | If an account is connected early, run its W2 story right after the W1 adapter story |
| **C-D2** | **Each capture channel is a leaf package with an injected client**: `@omnis/adapter-kakaotalk` (`KmsgClientLike`), `@omnis/adapter-linkedin` (`LinkedInPageLike` + the notification-email parser), `@omnis/adapter-whatsapp` (`BeeperClientLike`). The real client (spawning `kmsg`, driving Playwright, calling Beeper) is written only in the W2 story that has the gate | Same shape as Telegram's `TelegramClientLike` (US-B38), which let B38 ship on fixtures. Keeps `kmsg`, Playwright and `ws` out of every W1 test | — |
| **C-D3** | **The capture sidecar is `local-agent` on the mini, not a new app.** `local-agent` already runs as a LaunchAgent in the GUI session, already holds an authenticated, reconnecting WebSocket to the hub, and already has an outbox. ## 3. What US-C00 adds to the contract (verbatim; every later story copies these names)

- **Migration `packages/db/migrations/0015_phase_c.sql`** — seeds settings `delegation.allow_rules` = `[]`, `delegation.hermes_enabled` = `false`, `import.terminal_sessions` = `false`, `kakao.read_stable_since` = `null`; seeds jobs `terminal_import` (`*/5 * * * *`) and `followup_miss` (`15 23 * * *`).
- **`SettingKey`** (`packages/kernel/src/settings.ts`) gains the four keys above, with the same defaults in `SETTING_DEFAULTS`.
- **`packages/protocol/src/bridge.ts`**:
  - `HUB_METHODS` += `"capture.send"`, `"sessions.import_scan"`.
  - `BRIDGE_METHODS` += `"capture.items"`.
  - `runtime.registered` becomes a **request** that returns `{ runtime_id: string }` (the hub already upserts the row; it now `RETURNING id`). This is how `local-agent` fills `runtimeIds` (US-C01).
  - New zod schemas: `CaptureItemsParams`, `CaptureSendParams`, `ImportScanParams`, `ImportedSession`, `DelegateRunParams` (= `DelegationBrief` + `sig: string`).
  - `BRIDGE_ERRORS` is unchanged (`-32005` path denied, `-32006` approval required, `-32007` timeout, `-32008` cancelled, `-32009` rate limited already exist per A2 §3.4).
- **`packages/protocol/src/delegation.ts`** (new): `signApproval(token, approvalId, briefSha256): string` and `verifyApproval(token, approvalId, briefSha256, sig): boolean` — HMAC-SHA256 with the host's bridge token (`omnis.bridge.token.<host>`, which both ends already hold), `timingSafeEqual` on verify.

## 6. Prohibitions common to all stories

Inherited verbatim from the Phase B backlog §4 (no irreversible tool outside the approval gate; provider SDKs only inside adapter packages; append-only migrations; never delete or skip tests; no egress imports from `packages/agents/**`; `propose_*` only stores; no hard delete; never open A4 §10.2 excluded paths; no real credentials in tests; never read `~/.claude/.credentials.json`). Phase C adds:

1. **Never touch the mini's Hermes, omh or buzz setup, or port 8642.** Hermes tests use mock `fetch` and mock SSE only; S-A2-5 is Logan's.
2. **No channel send without the approval gate, and KakaoTalk sends are dry-run first** (US-C13). No test ever spawns `kmsg`, drives a browser, or opens a socket to Beeper.
3. **`delegate.run` and `capture.send` refuse anything without a valid hub signature** (`verifyApproval`). A non-empty `approval_id` is not proof.
4. **Terminal import opens only the two globs in C-D7.** A test asserts that a planted `~/.claude/.credentials.json` in the fixture root is never read.
5. **Synthetic fixtures say so** (`"provenance": "synthetic-from-docs"`). Fixtures with Korean text exist only where the test is about non-English input, and the fixture's `scenario` name says so (repo English-only rule).
6. **No new migration outside US-C00** (C-D8).
