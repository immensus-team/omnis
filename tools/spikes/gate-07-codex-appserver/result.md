- **decided_by**: Fable (agent), 2026-09-20 — based on the evidence above. The protocol round trip ran to completion (PASS); the model response path was not observed (re-run condition stated).
- **Notes**:
  - **Adjudicator (run.ts) design**: events are adjudicated by parsing `params.item.type`, not by substring-matching whole lines. Because the server sends the prompt back as a `userMessage` item, naive matching would **see only our own echo** and report that `item/started`/`item/completed` were observed (the `agentMessage` row A2 §4.2 requires would not be proven). The result line reports the user-side and agent-side item types separately.
  - **Three verdict values**: `pass` (exit 0) = protocol round trip completed **and** `turn.status="completed"` **and** an agentMessage item observed / `degraded` (exit 2) = protocol round trip completed but no model response observed / `fail` (exit 1) = protocol round trip failed. This deviates from the plan's original 2 values (`gate7_pass=true|false`, exit 0|1) — recording a turn where nothing happened because the limit was exceeded and a turn the model actually answered as the same green line would make the 2026-09-23 re-run meaningless.
  - **Regression check**: `npx tsx check.ts` (no Codex or network needed, 3 cases) — ① replaying the real measured log yields `degraded` (it is a failure if it reports pass), ② replaying the synthetic fixture (`fixtures/synthetic-agentmessage-pass.ndjson`, agentMessage + `status:"completed"`) yields `pass`, ③ replaying an echo-only log with the agentMessage lines removed yields `degraded`. Recorded logs can also be re-adjudicated directly with `npx tsx run.ts --replay <file>`. `fixtures/` is synthetic data, not measurement evidence (real measurements live in `evidence/`).
  - The Task plan's original turn-start method detection logic in `run.ts` (regex `/sendUserTurn|newTurn|userTurn/i` over `$defs` key names) did not fit this schema and could not be used as-is — the actual wire method names do not exist as `$defs` keys but as method-enum string literals inside the schema (`"thread/start"`, `"turn/start"`). It was changed to search the raw schema text for those literals (matching what `_probes/2026-09-20-cli-probes.md` had already confirmed).
  - `TurnStartParams` requires `threadId`, so `turn/start` cannot be sent on its own as the plan's original text assumed — a step was added to extract the thread id from the `thread/start` response and pass it in (a minimal correction consistent with A2 §4.2's "three-part thread/turn/item structure").
  - Raw logs are kept as `evidence/*.txt` rather than `run.log` (because of `.gitignore`'s `*.log`).
